# Vast Search Offers grant

**BLOCKED_UNVERIFIED_VAST_SEARCH_SCOPE.** Vast documents Search Offers under `misc`, which also includes endpoint and workergroup changes. Its constraints examples explain parameter restrictions for a documented instance-log action. They do not establish the exact Search Offers grant or the resulting effective permissions for this integration. A successful search, key name, or read-only tool annotation cannot establish those permissions. [Vast permissions](https://docs.vast.ai/api-reference/permissions) · [Vast authentication](https://docs.vast.ai/api-reference/authentication)

Mock setup bypasses credential handling entirely. Live mode and `doctor --live-search` report the same gate and direct the owner to the [Vast Console](https://cloud.vast.ai/). Do not give agents or T3 a full-access key, blanket `misc`, or a lifecycle key.

To enable live search in a future release, obtain provider-backed evidence for the exact grant and how it was provisioned on the destination account. Verify the documented read-only search request separately. Avoid mutation requests as permission probes. After that gate is met, the wizard must use a no-echo owner terminal prompt and a verified OS credential backend such as Windows Credential Manager. Pass only the profile identifier in client config and keep the key out of process arguments, logs, environment, and chat. A same-user process with broad shell access can often reach the same OS credential store. [Search Offers API](https://docs.vast.ai/api-reference/search/search-offers)
